Applique le kit `_playbook/anti-attribution/v1/` (lis son README). Il met en place la règle anti-signature IA en 4 couches : réglage de l'outil, consigne dans le fichier d'instructions racine, hook commit-msg versionné, script d'audit. Installe les fichiers tels quels (SHA-256 vérifiés), fusionne `settings.json` sans rien écraser, chaîne les hooks existants.
Ne modifie jamais l'identité git ni `core.hooksPath` : c'est une action de l'utilisateur (STOP, tu la lui indiques). Ne réécris jamais l'historique sans mon accord.
Teste d'abord dans un dépôt jetable (jamais dans le vrai) : message propre accepté, trailers (casse comprise), signature, nom d'outil et de modèle refusés, sujets de merge conformes acceptés, quasi-conformes refusés, audit sur la plage de départ. Supprime le jetable et vérifie qu'il n'existe plus. Chaque réglage d'outil est vérifié dans la doc de la version installée, sinon « non retrouvé ».
Réserves : un réglage d'attribution a été signalé comme ignoré dans certaines versions, d'où les quatre couches. Certains contextes (stores, contrats, droits d'auteur) exigent de déclarer l'usage d'une IA : vérifier avant de publier.
